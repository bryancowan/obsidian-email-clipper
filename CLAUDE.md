# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Package name: `obsidian-email-clipper` (PyPI / GitHub). Python module: `email_clipper`. CLI entry: `email-clipper`. Launchd label: `local.obsidian-email-clipper`.

## Commands

```bash
make dev          # create local .venv with editable install (run first)
make test         # run pytest (creates .venv if needed)
.venv/bin/pytest tests/test_frontmatter.py   # single test file
.venv/bin/email-clipper path/to/email.eml    # manual conversion

make install      # first-time launchd setup (runtime venv outside ~/Documents/)
make refresh      # sync code changes into live runtime venv
make reload       # restart launchd agent after plist changes
make logs         # tail conversion logs
make status       # show launchd agent state
```

## Architecture

The pipeline is: `.eml` → `parser` → `senders`/`url_builder` → `extract` → `markdown` → `frontmatter` → `writer` → `.md`.

**`cli.py:convert()`** orchestrates everything in order:
1. `parser.parse_eml()` — stdlib `email` parsing into `ParsedEmail` dataclass
2. `senders.lookup(from_email)` — returns a `SenderConfig` with publication-specific rules
3. `extract.preprocess(html)` — BeautifulSoup cleanup + extracts the "View in Browser" URL; unwraps table-based email layout into divs so `markdownify` doesn't produce mangled markdown tables
4. `url_builder.build()` — constructs canonical article URL when the VIB link is a tracker redirect
5. `markdown.html_to_markdown()` — `markdownify` conversion
6. `frontmatter.build()` — produces YAML matching Obsidian Web Clipper's exact format
7. `writer.write_note()` — writes `{title} - {YYYY-MM-DDTHHmmss±ZZZZ}.md` to the vault

**Two deployment contexts:**
- Dev: local `.venv/` at repo root, editable install via `pip install -e ".[dev]"`
- Runtime: `~/Library/Application Support/email-clipper/venv/` installed by `make install`. Lives outside `~/Documents/` because macOS TCC blocks launchd from reading `~/Documents`. `make refresh` syncs code changes there.

The launchd agent plist is generated at install time from `scripts/launchagent.plist.tmpl` (placeholders: `@APP_DIR@`, `@INBOX@`, `@LOGS@` — substituted by the Makefile). It uses `WatchPaths` on `~/Obsidian Inbox/`. When an `.eml` is dropped there, `scripts/process-inbox.sh` runs the CLI, moves successes to `processed/` and failures to `failed/`.

## Tests and fixtures

Tests in `tests/` run against synthetic `.eml` files in `tests/fixtures/`. These are generated by `tests/fixtures/build_fixtures.py` and committed so a fresh clone can `pytest` immediately. Regenerate with:

```bash
.venv/bin/python tests/fixtures/build_fixtures.py
```

The fixtures imitate real newsletter structure (table-based layout, tracking redirects, "View in browser" / "Follow Us" / "Unsubscribe" boundaries) without using any third-party copyrighted content. **Do not commit real newsletter `.eml` files** — they contain copyrighted prose.

CI is at `.github/workflows/test.yml` (Python 3.11/3.12/3.13 matrix on push + PR to `main`).

## Adding a newsletter sender

Add a `SenderConfig` entry to `senders.py:SENDERS` keyed by the `From:` address. If the newsletter has a predictable canonical URL pattern, add a builder function to `url_builder.py:BUILDERS` and reference it via `url_builder` in the config. The `is_tracker_redirect()` list in `extract.py` may also need updating for new tracker domains.

## Gotchas / decisions (don't undo these without a reason)

- **Layout tables MUST be unwrapped before markdownify.** `extract.unwrap_layout_tables()` rewrites `table/tr/td` → `div`. Without this, the entire newsletter body becomes one giant malformed markdown table on a single line. Confirmed against the Bloomberg fixtures — removing this regresses both.
- **Frontmatter is built by hand, not via PyYAML.** The Web Clipper template uses specific quoting and an unusual empty-value style (`note:` and `related:` with no value, no `null`). PyYAML's output diverges. `frontmatter.build()` emits the YAML manually to match exactly.
- **Inline tracker URLs are kept verbatim** (e.g. `links.message.bloomberg.com/s/c/...`). They're functional redirects but ugly. v1 deliberately makes no HTTP calls. To resolve them later, add a redirect-follow step in `extract.py` before the MD conversion.
- **Bloomberg slug rule**: apostrophes (straight `'` and curly `’`/`‘`) become hyphens, *not* stripped. `slugify()` strips by default; we pre-replace before slugifying. Tests in `tests/test_url_builder.py` pin both fixtures' real URLs.
- **Title-prefix stripping is per-sender** (`subject_prefix`). Publication identity is carried by tags, not the title. Bloomberg's title becomes `"GameStop ..."` not `"Money Stuff: GameStop ..."`, with `MoneyStuff` + `bloomberg` tags.
- **Filename timestamp = now (local tz)**, not email Date. This matches the Web Clipper template variable `{{time|date:"..."}}` so newsletter notes sort with web-clipped notes.
- **`source` fallback chain**: extracted "View in browser" → if that's a tracker redirect, run sender's `url_builder` → empty string for unknown senders. Tracker domains are listed in `extract.is_tracker_redirect()`.
- **Description = first prose paragraph after the title heading**, not the first block. Leading blocks may be image links / sponsor banners. See `_first_paragraph` in `cli.py` — it skips headings, image-only blocks, and any block whose link/image-stripped length is < 40 chars.
